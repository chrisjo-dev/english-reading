# 매일 일본어 읽기: 생성 절차 (일본어, ja)

예약 작업이 매일 아침 이 파일을 읽고 따른다. 대상은 JLPT N4~N5 수준의 한국인 일본어 학습자이고, 설명과 뜻은 모두 한국어로 쓴다.

## 난이도 규칙 (매우 중요)
- 지문은 **N5 위주 + N4 1문장** 정도로 쓴다. 문장은 4~6개, 한 문장은 짧게(대략 25자 안팎).
- 문체는 です・ます체로 통일한다. 반말, 경어(尊敬語・謙譲語), 어려운 관용구는 쓰지 않는다.
- 어휘는 N5~N4 범위에서 고르고, 주제에 꼭 필요한 N3 이상 단어는 지문당 1~2개까지만 쓰며 반드시 주요 단어(`words`)에 넣는다.
- 숫자, 요일, 시간, 날짜 표현을 하루에 한두 개 자연스럽게 넣는다(학습자가 자주 틀리는 부분).
- 스스로 난이도를 올리지 않는다.

## 후리가나 표기 (모든 한자에)
- 지문(`sentences[].en`), 주요 단어, 체크 포인트, 한 단계 위 어휘의 단어와 예문에 나오는 **모든 한자**에 `{한자|읽기}`로 읽기를 단다.
- 단어 단위로 묶고, 오쿠리가나는 밖에 둔다: `{食|た}べます`, `{新|あたら}しい`, `{毎朝|まいあさ}`, `{一人|ひとり}`.
- 숙자훈(今日, 大人 등)은 통째로 묶는다: `{今日|きょう}`, `{大人|おとな}`.
- 강조는 바깥에 감싼다: `**{近|ちか}く**`.
- 히라가나, 가타카나, 숫자에는 달지 않는다. 숫자는 한자 대신 아라비아 숫자를 써도 된다(`7{時|じ}`).

## 오늘의 소재 정하기 (지문을 쓰기 전에 수행)

**최근 내용 겹치지 않기**: 고르기 전에 `python3 -c "import json,glob; [print(p[-15:-5], json.load(open(p)).get('topic'), '|', ' '.join(s['en'] for s in json.load(open(p))['sentences'])[:200]) for p in sorted(glob.glob('content/ja/*.json'))[-14:]]"`로 최근 14편의 주제와 본문을 읽습니다. 주제는 다시 나와도 됩니다. 다만 최근에 쓴 지문과 같은 기사, 같은 사건, 같은 설명(예: '고장 난 물건을 가져오면 봉사자가 고쳐 준다'를 또 설명하기)을 반복하면 안 됩니다. 같은 주제를 고른다면 새로 생긴 일에만 초점을 맞추고, 이미 설명한 배경은 다시 쓰지 않습니다.
1. **오늘의 분야와 글의 형태** (Asia/Seoul 기준 요일):
   - 월: 생활 · 일기 (내가 한 일)
   - 화: 일본 문화 · 소개 (음식, 계절 행사, 장소)
   - 수: 사회 · 쉬운 뉴스
   - 목: 일과 학교 · 대화를 풀어 쓴 글
   - 금: 과학과 자연 · 쉬운 설명
   - 토: 여행과 장소 · 안내
   - 일: 계절과 날씨 · 짧은 이야기
   `category` 값: 생활·문화·여행은 `culture`, 사회·일과 학교는 `society`, 과학과 자연은 `science`, 계절과 날씨는 `future`가 아니라 `culture`. 기술 이야기면 `tech`.
2. **쉬운 뉴스 요일(수)**: WebSearch(ToolSearch로 불러오기, mode "standard")로 최근 1~2일의 가벼운 일본 소식을 찾는다. 쉬운 일본어 뉴스(NHK「NEWS WEB EASY」 등)가 검색 결과에 나오면 우선 참고한다. WebFetch로는 **검색 결과에 나온 주소만** 연다. 주소를 직접 추측해 열면 승인 요청에 걸려 실행이 멈춘다. 기사가 열리지 않으면 다른 검색 결과로 넘어가고, 두세 번 실패하면 3번(일반 글)으로 쓴다. 원문 문장을 옮기지 말고, 확인한 사실(숫자, 날짜, 장소) 2~3개로 새로 쓴다. 이때만 `source`를 채운다.
3. **그 밖의 요일**: 실제 사실을 지어내지 않는 일반적인 생활 글로 쓴다. 특정 가게, 사람, 수치를 실제인 것처럼 쓰지 않는다. `source`는 `null`.
4. **구조 다양화**: 아래 예시의 문장 흐름을 따라 하지 말고, 날마다 시작 방식과 문장 구조를 바꾼다. 무거운 소식(재난, 사망, 전쟁, 정치 갈등)은 피한다.

## 매일 생성할 형식 (content JSON 필드)
1. **지문** `sentences`: 4~6문장. 주요 단어는 `**…**`로 표시. N4 문장 하나에 `"b2": true`(사이트에 N4 배지로 보인다).
2. **주요 단어** `words`: 5~7개. `["{近|ちか}く", "근처"]`처럼 일본어(후리가나 포함) + 한국어 뜻.
3. **체크 포인트** `points`: 1~2개. 그날 지문에 실제로 나온 문법을 한국어로 짧게 설명한다. 조사(は・が・を・に・で), 동사 활용(ます형, て형, た형), 시간 표현, 조수사 가운데서 고른다. 지문 표현은 `` `…` ``로 감싼다.
4. **모범 해석** `answers`: 문장 순서대로 자연스러운 한국어 해석.
5. **한 단계 위 어휘** `advanced`: 6~8개. N3 수준 단어, 한국어 뜻, 혼동 주의(없으면 `null`), 지문 내용을 그 단어로 바꿔 쓴 예문(해당 단어는 `**…**`).
6. 그 밖의 필드: `topic`(한국어 주제어 2~8자, 예: "동네 빵집". 썸네일과 목록에 쓰인다), `title_ko`(페이지와 메일 제목. "오늘은 ___ 이야기예요"에 들어갈 자연스러운 한국어 명사구, 예: "동네의 작은 빵집"), `headline`(제목 아래 작게 보이는 일본어 제목. N5 수준의 짧은 제목으로 새로 쓰고 한자에는 후리가나 표기, 예: "{近|ちか}くのパン{屋|や}"), `chips`(`["N문장", "N5 위주", "N4 1문장", "약 3분"]`), `date`, `category`.

### 생성 예시 (형식 참고용, 내용과 흐름은 따라 하지 말 것)
- 지문: `{日曜日|にちようび}に、{友|とも}だちと**{公園|こうえん}**へ{行|い}きました。`
- 주요 단어: `["{公園|こうえん}", "공원"]`
- 체크 포인트: `{"title": "방향의 へ", "body": "`{公園|こうえん}へ{行|い}きました`의 へ는 '~로, ~에'처럼 가는 방향을 나타내요."}`
- 한 단계 위 어휘: `{"word": "{散歩|さんぽ}", "meaning": "산책", "confuse": null, "example": "{公園|こうえん}を**{散歩|さんぽ}**しました。"}`

## 결과물 만들기와 올리기

작업 디렉터리는 사이트 저장소 `chrisjo-dev/english-reading`의 clone입니다(main 브랜치). 날짜는 Asia/Seoul 기준 오늘 `YYYY-MM-DD`입니다. **반드시 맨 먼저 `TZ=Asia/Seoul date +%F`를 실행해 그 결과를 오늘 날짜로 쓰세요.** 실행 알림이나 시스템 메시지에 적힌 시각은 UTC라서 새벽에는 하루 전 날짜가 됩니다. 그 날짜를 쓰면 안 됩니다. 요일도 `TZ=Asia/Seoul date +%a`로 정합니다.

1. **이미 올라간 날인지 확인**: `content/ja/YYYY-MM-DD.json`이 이미 있으면 새로 만들지 말고 끝냅니다.
2. **content JSON 쓰기**: `tools/render.py` 맨 위 설명의 형식 그대로 `content/ja/YYYY-MM-DD.json`을 씁니다. 모든 문자열은 일반 텍스트(HTML 태그 금지).
3. **검증**: `python3 tools/render.py ja YYYY-MM-DD`를 실행해 오류 없이 끝나는지 확인합니다. 만들어진 `ja/YYYY-MM-DD/index.html`에서 `{`나 `|`가 남아 있지 않은지(후리가나 표기 실수) `grep -c '[{|]' ja/YYYY-MM-DD/index.html`로 확인하고, 0이 아니면 JSON을 고칩니다(페이지의 다른 곳에도 `{`가 있으니 지문 부분을 직접 열어 확인). 확인이 끝나면 `git checkout -- . && git clean -fd -- ja/YYYY-MM-DD`로 되돌린 뒤 content 파일만 남깁니다.
   그다음 `python3 tools/check_content.py ja YYYY-MM-DD`를 실행합니다. `::error`(화면에 그대로 보이는 마크다운 기호 등)가 나오면 JSON을 고쳐 다시 실행합니다. `::error`(최근 지문과 내용 겹침)가 나오면 다른 소재로 다시 쓰고, 겹친 채로 올리면 발행 단계에서 비축분으로 바뀝니다. `::warning`(출처 없이 구체적 수치)이 나오면 출처를 달거나 수치를 빼고, 학습용으로 지어낸 사례라면 JSON에 `"example": true`를 넣습니다(페이지에 "지어낸 이야기"라고 표시됩니다).
4. **push**: `git add content/ja/YYYY-MM-DD.json && git -c user.name="chrisjo" -c user.email="wonsang.dev@gmail.com" commit -m "Add ja YYYY-MM-DD: 주제어" && git push origin HEAD:main`. 커밋 메시지에 Co-Authored-By 같은 작성자 줄을 붙이지 마세요. 다른 브랜치로 push하지 마세요. 거절되면 `git pull --rebase origin main` 후 한 번만 다시 push합니다.
5. **마지막 답변**: 한두 문장과 페이지 주소 `https://read.wspace.ai.kr/ja/YYYY-MM-DD/`, 출처가 있으면 `출처: [기사 제목](URL)` 한 줄. 실패했다면 원인을 분명히 적습니다.
