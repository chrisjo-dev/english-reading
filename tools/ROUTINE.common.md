# 공통 지문 규칙 (영어, 일본어, 독일어)

세 언어 루틴이 지문을 쓰기 전에 이 파일을 먼저 읽는다. 언어별 수준, 후리가나, 끊어 읽기, 문장 길이, 소재의 지역성은 각 언어 루틴을 따른다. 두 파일이 부딪히면 언어별 표기와 수준은 언어 루틴을, 그 밖의 것은 이 파일을 따른다.

## 1. 요일 구조 (Asia/Seoul 기준)

| 요일 | 유형 | `fit` 값 | 출처 |
|---|---|---|---|
| 월, 수, 금 | 소식 (기사) | `news` | 필수 |
| 화, 목 | 원리, 문화 설명 (사실 확인) | `explain` | 필수 |
| 토, 일 | 생활 글 (대화, 경험담, 가상 인물) | `life` | 없음 (`source`는 `null`) |

content JSON에 그날 유형을 `fit` 필드로 적는다. 예: `"fit": "news"`. 소재를 나타내는 한국어 명사 2~4개를 `keywords` 필드로 적는다. 예: `"keywords": ["아르바이트", "서점", "첫 출근"]`.

**출처 실패 규칙 (세 언어 공통)**: 소식이나 설명 날에 출처를 찾지 못하면 사실을 지어내지 않고 실제 사실을 쓰지 않는 일반 글로 쓴다. 마지막 답변에 이유를 적고, `fit`은 원래 요일 유형을 그대로 둔다.

## 2. 사실 규칙

- 소식 날: 없는 발언이나 경험을 지어내지 않는다. 기사에 실제로 나온 발언만 인용한다. 독자에게 말을 거는 문장은 쓸 수 있다(예: "Imagine you ...").
- 설명 날: 확인한 사실만 쓴다.
- 생활 글 날: 가상 인물로 대화나 경험담을 쓴다. 실제 사람, 가게, 수치인 것처럼 쓰지 않는다.
- 숫자는 소식에 꼭 필요한 것만 남긴다.

## 3. 문법 배정

### 후보 스크립트 `tools/grammar_pick.py`

- **호출 시점**: 지문을 쓰기 전.
- **명령**: `python3 tools/grammar_pick.py <언어> <수준> --day YYYY-MM-DD [--skip N]`. 수준은 `a`, `b`. 오늘 유형(`fit`)은 날짜의 요일로 정한다. `--skip 1`, `--skip 2`가 다음 후보다.
- **이력**: `content/<언어>/*.json`의 `grammar` 필드.
- **목록**: `tools/grammar/<언어>.json`에서 수준이 같고 `fit`에 오늘 유형이 든 항목.
- **출력**: 후보 3개. 후보가 없어도 종료 코드 0으로 끝난다.
- **순서**: 기록 없는 항목 먼저, 그다음 가장 오래전에 쓴 순서, 같으면 목록 순서.
- **기존 지문 소급 없음**: 지난 지문은 `grammar`를 채우지 않는다. 이력 0에서 목록 순서대로 시작한다.

### 쓰는 법

1. 후보 스크립트로 수준별 후보 3개를 받는다.
2. 소식 날은 소식에 맞는 문법만 쓴다. 생활 글 날은 조건문, 경험, 의지 표현까지 폭넓게 쓴다.
3. 후보 중 소재에 자연스러운 1~2개를 중급 지문에, 기초 후보에서 1개를 기초 지문에 넣는다.
4. 모두 어색하면 다음 후보를 받는다. 다음 후보는 최대 2번(총 3회)까지 받는다. 그래도 어색하면 `grammar`를 빈 목록으로 두고 발행한다. 예약 작업은 이 단계에서 멈추지 않는다.
5. 쓴 문법을 content JSON의 `grammar` 필드에 적는다. 예: `"grammar": {"b": ["b-present-perfect"], "a": ["a-will"]}`.

### 추적과 점검

- 문법 사용 기록의 기준은 `grammar` 필드의 `id`다.
- `pattern`은 보조 점검이다. 기초와 중급의 `pattern`이 같아도 된다. 어느 수준에서 썼는지는 `id`로 구분한다.
- `pattern`은 문장 하나씩, 굵게 표시와 후리가나를 제거한 문장에 돌린다. 지문 전체를 한 덩어리로 돌리지 않는다.
- `pattern`이 `null`인 항목은 자동 점검하지 않는다. 형태가 흔해 정규식으로 구분할 수 없는 항목이다.

## 4. 체크 포인트

`points`는 2개로 쓴다.
- 1개: 그날 배정된 문법 설명. 지문의 실제 표현을 인용한다.
- 1개: 자유. 그날 지문에서 걸릴 만한 표현을 고른다.

`grammar`가 빈 목록인 날은 2개 모두 자유로 쓴다. 특정 표현을 매일 반복하지 않는다. 최근 14일의 체크 포인트 제목과 겹치면 다른 것을 고른다.

## 5. 소재 반복 방지

- 소재를 고르기 전에 `python3 tools/check_content.py --topics <언어> YYYY-MM-DD`로 언어별 최근 90일의 `topic`, `title_ko`, `keywords`를 확인한다.
- 같은 소재, 같은 상황, 같은 장면 구성은 쓰지 않는다. 예: 일본어 `첫 아르바이트`와 `서점 아르바이트`, 영어 `로보택시` 두 번.
- 뉴스는 후속 사건으로 핵심 사실이 새로울 때만 예외이며, 다른 각도로 쓴다.

## 6. 단어 재사용

최근 14일의 `words`에서 일반 단어를 고른다. 전문 용어와 고유명사는 고르지 않는다.
- 소식, 설명 날: 1개, 자연스러울 때만.
- 생활 글 날: 2~3개 목표.

## 7. 제목과 뜻

- `title_ko`: 원문 제목을 옮기지 말고 편집자가 새로 붙이는 15자 안팎의 자연스러운 한국어 명사구로 쓴다.
- 단어 뜻: 한국어 사전의 대응어로 짧게 쓴다. 풀어 쓴 설명을 쓰지 않는다. 뜻에 외국어 표기를 넣지 않는다.

## 8. 검사

`check_content`의 `::error`는 반드시 고친다. `::warning`은 해당 필드나 소재를 고친 뒤 다시 검사한다. 2026-11-08 이후 지문에 아래를 경고한다. 경고는 발행을 막지 않고, 비축분에는 적용하지 않는다.

- `fit`이 없거나 요일과 다름
- `news`, `explain` 날에 `source` 없음
- `grammar`가 없거나, id가 목록에 없거나, 적은 문법의 `pattern`이 지문의 어느 문장에도 없음
- `keywords` 없음
- 영어 중급 문장이 12~26단어를 벗어남(`b2` 문장은 30단어까지)
- 최근 90일 지문과 `keywords`, `topic`, `title_ko`의 2자 이상 한국어 낱말이 겹침
